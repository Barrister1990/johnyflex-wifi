WiFiHub Ghana Master Software Requirements Specification (Version 2.1)

This document expands Version 2.0 with product features for Ghana
hotspot operators, cafés, schools, churches, hostels, transport
terminals, communities, and resellers.

================================================================== 1.
PRODUCT SUMMARY
==================================================================

WiFiHub Ghana is a cloud-based Wi-Fi hotspot billing platform operated by
a SINGLE company (one operator account). That company can run many
locations (Accra, Kumasi, Takoradi, Tamale, …), sell prepaid packages,
vouchers, and monthly subscriptions, accept Paystack, and attach routers
(MikroTik first). It is NOT a multi-tenant SaaS marketplace for unrelated
operators.

Owners manage multiple locations from one dashboard. Customers buy or
renew access, view usage, download receipts, and manage devices through
a self-service portal. Hardware (Starlink backhaul, MikroTik, UniFi,
etc.) attaches through a router abstraction layer so business logic
never depends on a single vendor.

Development Phase:
- Router hardware is NOT required.
- Router actions are simulated using a Router Integration Layer.
- Local JWT auth + JSON file store may be used before Supabase.

Production Phase:
- Support MikroTik first.
- Future adapters: UniFi, pfSense, OpenWrt, Starlink-aware backhaul.
- Supabase PostgreSQL + Auth, Vercel hosting.

================================================================== 4.
FEATURE SPECIFICATIONS (PRODUCT IDEAS TO SHIP)
==================================================================

------------------------------------------------------------------ 4.1
Customer Self-Service Portal
------------------------------------------------------------------

Customers can:
- Buy internet (prepaid packages)
- Renew packages
- View usage (time / data remaining)
- Download receipts (PDF or printable)
- Manage devices linked to their account

Portal entry points:
- QR scan at hotspot captive redirect
- Direct /portal/[hotspotId]
- Self-service account area after identifying via email / voucher code

------------------------------------------------------------------ 4.2
Voucher System
------------------------------------------------------------------

Owners and resellers generate prepaid vouchers for offline sale.

Example:
  Face value: GH₵5
  Code:       WF-83KD-22P9

Requirements:
- Batch generate N vouchers for a package or fixed amount
- Unique codes (human-readable, hard to guess)
- Status: unused | redeemed | expired | void
- Optional expiry date and max devices
- Printable / CSV export for café and shop resellers
- Redeem on portal: enter code → create session → authorize device

------------------------------------------------------------------ 4.3
Device Management
------------------------------------------------------------------

Track per connected / known device:
- Device name
- MAC address
- Phone (optional)
- Current package
- Remaining time
- Current speed (from bandwidth profile / live router stats)
- Hotspot / location
- Session status (active | expired | revoked)

Owner UI: searchable device list, revoke / disconnect, force re-auth.
Customer UI: list and rename own devices (within plan limits).

------------------------------------------------------------------ 4.4
Subscription Billing
------------------------------------------------------------------

In addition to prepaid access, support recurring monthly plans.

Examples:
  Basic     GH₵80/month   Unlimited
  Premium   GH₵150/month  Unlimited + higher speed

Requirements:
- Plan catalog (price, speed profile, data cap or unlimited)
- Paystack recurring or renewal reminders + manual renew
- Bind subscription to customer + hotspot (or all owner locations)
- Grace period and suspend on failed renewal
- Coexist with prepaid packages and vouchers

------------------------------------------------------------------ 4.5
Router Dashboard
------------------------------------------------------------------

Per router / hotspot live operations view:
- Router online / offline
- Internet / backhaul status
- Connected users count
- Bandwidth (up / down)
- CPU
- Memory
- Traffic (time-series)

Fed by adapter getRouterStatus() and telemetry polls. Mock adapter
returns simulated metrics in development.

------------------------------------------------------------------ 4.6
Captive Portal Builder
------------------------------------------------------------------

Hotspot owners customize the customer-facing portal:
- Logo
- Brand colors
- Welcome message
- Background image
- Visible packages (and voucher redeem entry)
- Terms & conditions

Stored as portal_theme / portal_config per hotspot (or owner default
with per-site overrides). Preview before publish.

------------------------------------------------------------------ 4.7
Analytics
------------------------------------------------------------------

Charts and summaries for:
- Revenue
- Users (unique customers / devices)
- Bandwidth (when router telemetry available)
- Package sales (and voucher redemptions)
- Peak hours

Existing owner analytics (revenue, payments, sessions, top packages,
by hotspot) expand to include bandwidth and peak-hour heatmaps.

------------------------------------------------------------------ 4.8
Multi-location Support
------------------------------------------------------------------

One owner manages many sites from one dashboard, for example:
- Accra
- Kumasi
- Takoradi
- Tamale

Each location is a Hotspot (SSID, address, GPS, QR, equipment, portal
theme). Packages may be owner-wide or assigned per location.
Analytics, reports, sessions, and payments filterable by location.

================================================================== 5.
ROUTER ABSTRACTION
==================================================================

Interface (minimum):
authorizeDevice() revokeDevice() disconnectDevice() createSession()
endSession() applyBandwidthProfile() getConnectedDevices()
getRouterStatus()

Development: update database only; return mock success + mock metrics.
Production: MikroTik first; then UniFi, pfSense, OpenWrt; Starlink as
backhaul catalog item (pair with AP/gateway for captive control).

Equipment catalog (searchable): Starlink, MikroTik, UniFi, TP-Link,
pfSense/OPNsense, OpenWrt, generic, mock.

================================================================== 6.
PAYMENT LIFECYCLE
==================================================================

Prepaid / voucher:
Customer -> Select Package or Enter Voucher -> Paystack (if paid) ->
Verify -> Store Payment / Mark Voucher Redeemed -> Create Session ->
Router Adapter -> Internet Active

Subscription:
Customer -> Choose Monthly Plan -> Paystack Checkout / Mandate ->
Verify -> Activate Subscription -> Authorize Devices per plan rules

Webhook validation is mandatory. Every payment must be idempotent.

==================================================================

================================================================== 16.
AI IMPLEMENTATION RULES
==================================================================

- Use TypeScript everywhere.
- Keep business logic independent of router implementation.
- Use repository/service architecture.
- Never hardcode secrets.
- Use Supabase Row Level Security in production.
- Write reusable React components.
- Use server actions or API routes only for privileged operations.
- Every feature should have validation and error handling.
- Every payment must be idempotent.
- All modules should be independently testable.
- Prefer owner-wide packages with optional per-location assignment.
- Document new modules in this SRS before large builds.

================================================================== 17.
LONG TERM VISION
==================================================================

WiFiHub Ghana should be the operational backbone for a Ghana Wi-Fi
business: one company configures packages and subscriptions, sells
vouchers through cafés and shops, customizes captive portals, accepts
Paystack, generates QR codes, manages devices across its locations, and
connects Starlink / MikroTik / UniFi gear with minimal setup.
